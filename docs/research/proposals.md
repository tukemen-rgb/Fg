# 提案（役割①の出力）

毎時、役割①がユーザー満足・収益・信用の観点で 1 件書く。新しいものを上に。
役割②はここの最新を読んで設計する。標準制約（対外発信しない・金額/契約を
決めない・経営ゲートの数値を変えない・main へ push しない）に触れる提案は
**要判断** と明記し、人が決めるまで役割②以降に流さない。

書式:

## <日時> <提案名>
- 状態: 未設計 / 設計済み / 実装済み / 要判断
- 何を: / なぜ: / 期待効果: / 根拠の事例: case-studies.md の番号
