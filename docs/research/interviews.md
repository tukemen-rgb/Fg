# 制作者インタビュー（型と記録。実施は人）

経営ゲート条件「制作者インタビュー 10 件」の受け皿。
型の根拠は docs/research/case-studies.md の 5（Postmortem）・6（The Mom Test）。

## 運用規則

- **実施・連絡・依頼文の送信は人（社長）**。このファイルは台本と記録の器
- 記録は事実のみ。相手は**ハンドル名のみ**（本人が公開している範囲）で書き、
  本名・所属・連絡先は書かない（git 履歴は消せない）
- 発言の引用は**本人が同意した範囲だけ**。同意の範囲を記録に残す
- **「1 件」と数える条件 = 質問票を完走し、記録が完備していること**。
  数合わせの薄い聞き取りは数えない
- 謝礼の有無・金額はここで決めない（決めるなら人）

## 質問票 v1

**v2 は第 1 巡（5 件）が終わってから作る。** 途中で設問を変えると
1〜5 件目と比べられなくなる。

意見や未来の話（「何があれば使いますか」）は聞かない。
**過去の行動の事実**だけを聞く。

1. 最近ゲームを公開したのはいつ・どこでしたか
2. その公開先はどうやって決めましたか
3. 公開までで一番時間を取られたことは何でしたか
4. （GAMEYARD を試した人）どこで詰まりましたか
   （試していない人）いま使っている場所で困っていることは何ですか
5. 公開後、感想や数字はどう見ていますか

締め（Postmortem 形式・同数で聞く）:

- 最近の公開で**良かったこと 3 つ**
- 最近の公開で**詰まったこと 3 つ**

## 記録テンプレート（1 件 1 節。新しいものを上に）

```
## <番号>. <日時> <ハンドル名>
- 経路: <どこで知り合い、どう依頼したか>
- Q1〜Q5 の回答: <事実のみ>
- 良かったこと 3 / 詰まったこと 3:
- 引用同意の範囲: <全文可 / 要約のみ / 引用不可>
- 効く成果: <下の 6 つから 1 つ / 該当なし>
- 学び: <1 行>
```

「効く成果」の選択肢（README の経営ゲート）:

- 投稿完了率 50%以上
- 新規投稿作品 10本
- 週次アクティブプレイヤー 100人
- 投稿作品の累計プレイ 300回
- 制作者インタビュー 10件
- 再訪率または7日継続率を計測可能にする

**迷ったら「該当なし」。無理に当てはめない**
（当てはめると、効かない改善が優先されることがある）。

## 声かけの記録（0 件）

- **インタビューに至らなかった声かけもここに残す。** 台帳（下）は
  「聞けた」の記録で、この表は「声をかけた」の記録
- 相手は**ハンドル名のみ**（本人が公開している範囲）。断られた相手に
  重ねて声をかけない
- **声をかけるのは人**。この表は結果を書き留める場所

| 日付 | 相手（ハンドル） | 経路 | 結果 |
| --- | --- | --- | --- |

結果は**返信なし / 断り / 話を聞けた / 投稿に至った**のいずれか。
「話を聞けた」は台帳の番号（例: 台帳 3）も書く。
