# 月次経営レコード（内部文書）

毎月 1 節を追記する（新しい月を上に）。**公開・共有の判断は人（社長）。**

## 運用規則

- **事実だけ書く。** それらしい数字を埋めない
- 収支がゼロの月は**ゼロと記録する**
- 計測できていない指標は「未計測」と書く
- 収支の実額は人にしか分からない。**AI が書けるのは「人の入力待ち」の明示まで**。
  人が記入したら以降その行は人の領域
- 金額・価格の**決定**はここでしない（記録のみ）
- git 履歴は消せない。取引先名・個人の報酬などの秘匿情報は、公開範囲を
  人が決めるまで書かない

## A 指標の集計手順（新規投稿作品数/週）

人が export を渡せば、誰がやっても同じ数字になるように定義を固定する。
**定義の変更は人の判断として、このファイルに日付つきで記録する。**

1. **入力**: 本番の投稿レコードの export を人に依頼する。依頼する列は
   **`slug` と `createdAt` の 2 つだけ**（作者ハンドル・メールなどの
   個人データはこのリポジトリに持ち込まない）。`createdAt` は
   ISO 8601 UTC（例: `2026-01-02T00:00:00.000Z`。site
   `server/store.test.mjs` で確認した形式）
2. **週の区切り**: `createdAt` を JST（UTC+9）に変換し、**月曜 00:00 始まり**
   の週に割り当てる。週の表記はその週の月曜の日付（例: `w08-03`）
3. **数え方**: その週に入るレコードの件数。公開/非公開を区別できる列が
   export に無い場合は**総数として数え、備考にその旨を書く**
4. **記録**: 該当月の KPI 表「今月実績」に週ごとの件数を書き
   （架空の例: `w01-05: 2 / w01-12: 5`）、備考に export の取得日を書く
